## Features

- **Real-time Collaboration**: Multiple users can draw simultaneously with instant synchronization
- **Smooth Drawing**: Powered by `perfect-freehand` for natural, pressure-sensitive strokes
- **Touch Support**: Works on both desktop and mobile devices
- **Drawing Tools**:
  - Color picker
  - Adjustable brush sizes
  - Undo functionality
- **Player Figures**: каждый игрок выбирает форму и цвет человечка, статус в игре показывает плитка и жетон
- **Background Doodle**: в лобби можно порисовать прямо по фону страницы и выгрузить каракули в PNG
- **Responsive Design**: Optimized for various screen sizes

## Tech Stack

- **Frontend**: React 19 with TypeScript
- **State Management**: Effector
- **Real-time Database**: InstantDB
- **Drawing Engine**: perfect-freehand, lazy-brush
- **Routing**: Wouter
- **Build Tool**: Vite
- **Styling**: CSS

## Prerequisites

- Node.js (version 16 or higher)
- npm or yarn package manager

## Installation

1. Clone the repository:

```bash
git clone <repository-url>
cd scribble
```

2. Install dependencies:

```bash
npm install
```

3. Configure InstantDB:
   - The app uses InstantDB for real-time synchronization
   - Current configuration uses a demo ID in `src/config.ts`
   - For production, you'll need to set up your own InstantDB instance

## Development

Start the development server:

```bash
npm run dev
```

The application will be available at `http://localhost:5173` (or the port shown in your terminal).

## Available Scripts

- `npm run dev` - Start development server
- `npm run server` - Start the game server (needs `.env` with `INSTANT_APP_ID` and `INSTANT_APP_ADMIN_TOKEN`)
- `npm run build` - Build for production
- `npm run check-types` - Run TypeScript type checking
- `npm run deploy` - Build and deploy to GitHub Pages
- `npx instant-cli@latest push` - Push new schema for Instand DB

## Deploy (backend)

Сервер ведёт таймер ходов. **Без него игра встанет**: как только время на рисунок
истекает, ход переключает именно он, клиент это больше не делает.

Локально:

```bash
cp .env.example .env   # заполнить из instantdb.com/dash
npm run server         # или: docker compose up -d --build
```

**Инстанс должен быть один на приложение.** Защита от повторного завершения хода
живёт в памяти процесса, так что второй сервер на том же `INSTANT_APP_ID`
продублирует события конца хода и перевыберет слова. Гоняешь локальный `npm run
server` — погаси контейнер на дроплете, или используй отдельное приложение.

|         |                                                             |
| ------- | ----------------------------------------------------------- |
| Дроплет | `134.209.227.168`, рядом чужие сервисы                      |
| Каталог | `/sites/scribble`                                           |
| Образ   | `ghcr.io/joxter/scribble/backend`, тег = sha коммита        |
| Портов  | не слушает, входящий трафик не нужен                        |
| Логи    | `docker compose -f docker-compose.prod.yml logs -f backend` |

На боксе ничего не собирается: CI (`.github/workflows/publish.yml`) прогоняет
тесты, собирает образ и кладёт в ghcr.io, дроплет только тянет. Сборки нет и в
CI — нода стрипает типы при загрузке, образ это зависимости плюс исходники.

### Первая установка

Порядок обязателен: `update.sh` тянет образ по sha текущего коммита, поэтому до
зелёного CI он откажется работать — это защита, а не помеха.

```bash
git clone https://github.com/Joxter/scribble.git /sites/scribble
cd /sites/scribble

# Админский токен обходит все правила доступа приложения — только сюда,
# не в репозиторий.
cp .env.example .env && nano .env
# Телеграм-бот тот же, что шлёт бэкапы sfw-game, и chat id там уже определён
grep '^TG_' /sites/sfw-game/.env >> .env
chmod 600 .env

./update.sh
```

### Обновление

```bash
cd /sites/scribble && ./update.sh
```

Пуш в master запускает CI; `update.sh` до появления образа отказывается
деплоить, вместо того чтобы молча выкатить вчерашний. HTTP-ручки у сервера нет,
поэтому вместо health-check скрипт смотрит, что контейнер через 5 секунд всё
ещё `running` — почти все способы выкатиться сломанным (битый `.env`, ошибка в
импорте, мёртвая подписка) роняют процесс сразу.

### Уведомления в телеграм

Через **@joxter_alert_bot** — того же, что шлёт бэкапы sfw-game (см.
`sfw-game/docs/deploy.md`, там же как достать токен, если `.env` соседа пропал).
Без `TG_BOT_TOKEN`/`TG_CHAT_ID` сервер просто молчит, ошибок это не создаёт.

| Событие                         | Что в сообщении                                   |
| ------------------------------- | ------------------------------------------------- |
| Игра началась                   | комната, сколько игроков и кругов                 |
| Игра закончена                  | комната, сыграно кругов, финальный счёт с именами |
| Подписка на InstantDB закрылась | сервер перезапускается, игры пока встали          |
| Сервер запустился               | подтверждение выката                              |

Отправка ничего не ждёт и никогда не бросает: телеграм лежит — игра идёт
дальше. О каждом ходе и о чате сознательно не сообщаем, это был бы шум.
После рестарта сервер не рассылает «игра началась» по уже идущим комнатам —
первый снапшот подписки это текущее состояние, а не новые игры.

## Key Components

### Canvas (src/drawing/Canvas.tsx)

The main drawing component that handles:

- Mouse and touch events for drawing
- Coordinate transformation for responsive design
- Real-time stroke rendering
- Integration with the drawing state

### Database (src/DB.ts & instant.schema.ts)

InstantDB integration for:

- Real-time data synchronization
- Canvas state persistence
- Multi-user collaboration

## Configuration

The app includes configuration options in `src/config.ts`:

- Canvas size settings
- Brush smoothing parameters
- Demo/party ID for database operations

The project is configured for GitHub Pages deployment:

```bash
npm run deploy
```

## Development Notes

- Схема БД лежит в `instant.schema.ts`; после её изменения нужен `npm run push-instant`, иначе запись новых полей будет падать

- The app uses a demo configuration with a hardcoded party ID
- The drawing engine uses SVG paths for smooth, scalable strokes
- Touch events are handled for mobile compatibility
